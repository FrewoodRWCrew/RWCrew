Gebruikte tools

Elke technologie, bibliotheek en dienst waarmee RWCrew gebouwd is en draait: wat ze doet, waar je ze tegenkomt en waarom ze gekozen is.

Doelgroep: iedereen. De tabellen zijn ook een naslagwerk voor ontwikkelaars.

Tools en technologieën

Iedereen
De frontend is geschreven in TypeScript met Next.js en React, opgemaakt met Tailwind CSS en kant-en-klare onderdelen van shadcn/ui. De backend is geschreven in Python met FastAPI en SQLAlchemy; de database is PostgreSQL. Alles draait in Docker op een Linux-server achter Nginx, en wordt automatisch gedeployed met GitHub Actions. Gekozen is telkens voor breed gebruikte, gratis, goed gedocumenteerde tools, zodat nieuwe teamleden er makkelijk informatie over vinden.

De Python 3.14-beperking

De ontwikkel-pc en de backend-container draaien Python 3.14, een zeer recente versie. Veel populaire Python-pakketten bevatten stukken in C of Rust die voor elke Python-versie apart gecompileerd moeten worden. Voor een gloednieuwe Python-versie zijn die voorgecompileerde versies (wheels) er soms nog niet, en dan moet je zelf een C/Rust-compiler installeren.

Daarom werd bij elke keuze bewust een pakket genomen dat puur Python is, of de standaardbibliotheek:

Bewuste keuzes door de Python 3.14-beperking

hashlib.pbkdf2_hmac (standaard)passlib / bcrypt
httpx rechtstreeks naar Resendeen apart mailpakket

Claude Code en CLAUDE.md

RWCrew is ontwikkeld met de hulp van Claude Code, een AI-programmeerassistent van Anthropic die in de terminal of in VS Code werkt. Je beschrijft in gewone taal wat je wilt ("voeg een mailinglijst toe aan module 3"), en Claude Code leest de bestaande code, stelt wijzigingen voor, voert ze uit en draait de tests. De dichte, uitleggende commentaarstijl en de consequente opbouw per module zijn mee daardoor ontstaan.

Het bestand CLAUDE.md in de hoofdmap van de repository is het projectgeheugen: Claude Code leest het bij elke start automatisch en volgt de afspraken die erin staan (architectuur, valkuilen, codeerafspraken, hoe je lokaal alles opstart). Daardoor maakt de assistent niet telkens dezelfde fouten opnieuw. Voor mensen is het de beknoptste samenvatting van het project.

Werk je met Claude Code (of een andere AI-assistent), houd dan deze regels aan:
  • Laat de assistent nooit zonder controle naar main pushen: lees elke wijziging na zoals je die van een collega zou nalezen.
  • Ontdek je een nieuwe valkuil of maak je een nieuwe afspraak, zet die dan in CLAUDE.md. Zo profiteren mensen én de assistent ervan.
  • Geef nooit geheimen (wachtwoorden, API-sleutels, .env-inhoud) aan de assistent als dat niet nodig is.
  • Laat de assistent de tests draaien en de documentatie bijwerken als deel van de taak.

Afhankelijkheden bijwerken

Bibliotheken krijgen regelmatig updates met oplossingen voor beveiligingsproblemen. Spreek af dat iemand ze bijvoorbeeld één keer per kwartaal (en niet vlak voor een festival) nakijkt:

  • Frontend: npm outdated toont wat verouderd is; npm audit toont gekende beveiligingsproblemen. Werk bij met npm install <pakket>@<versie>, test lokaal (npm run build) en commit package.json én package-lock.json.
  • Backend: .venv/Scripts/pip list --outdated. Pas de versie aan in requirements.txt, installeer, draai alle tests (pytest) en commit.
  • Grote versiesprongen (bv. Next.js 16 naar 17, of een nieuwe hoofdversie van FastAPI) apart en bewust doen: lees de migratiegids van die tool, werk op een aparte branch en test grondig op test.
